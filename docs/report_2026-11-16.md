# Pure GRPO vs SFT + GRPO vs GFlowNet on Qwen3-8B (16 Nov)

**Model.** Qwen3-8B, thinking off. Every method trains a LoRA adapter (rank 32, all attention and
MLP layers, ~87M parameters); the base weights stay frozen. One seed per method.

## 1. Training data and reward

Each training step draws **16 prompts** from a fixed pool of 2,000 (overlap with the test sets removed):

| Pool | Source | Per step |
|---|---|---|
| Harmful + prefill (a compliant opener such as "Sure, here is" is forced onto the reply; 26 training phrases) | BeaverTails | 8 |
| Harmful, plain | BeaverTails | 2 |
| Benign but harmful-looking | OR-Bench-80k | 3 |
| Maths | GSM8K train | 3 |

**Reward** (in [0, 1], scored by WildGuard, which is not used in evaluation):

- harmful prompt → **1 − P(reply is harmful)** (for prefilled prompts the judge sees prefill + continuation)
- benign prompt → **1 − P(reply is a refusal)**
- maths prompt → **1 if the final answer is correct, else 0**

## 2. Methods

**Pure GRPO** (30 steps)
1. Sample **8 replies** per prompt from the current model (temperature 1.0, ≤ 512 tokens): 128 replies.
2. Score them with the reward above.
3. Advantage within each group of 8: A = (reward − group mean) / group std. Groups whose rewards
   differ by less than 0.05 get A = 0, so WildGuard noise between equally safe replies is not learned.
4. Loss per reply token: **−A · log π(token) + 0.01 · KL(π ‖ π_untuned)**.
5. One gradient update per step (lr 1e-4, gradient clip 1.0).

**SFT + GRPO**
1. *SFT (rejection sampling):* for each of the 2,000 prompts, sample **4 replies** from the untuned
   model (temperature 0.7) and score them. Keep the best one if its reward ≥ 0.5; 1,868 kept.
2. Train on the kept replies with the ordinary next-token loss on reply tokens only (1 epoch,
   batch 16, lr 1e-4, 117 updates).
3. *GRPO:* start from the SFT adapter and run the same 30 GRPO steps as above (KL to the untuned model).

**GFlowNet (trajectory balance, TB)** (30 steps; same prompts, 8 sampled replies, reward, LoRA and lr as GRPO)
- Target: sample replies in proportion to **π_untuned(y|x) · exp(r/τ)**, i.e. log-reward
  **log R = log π_untuned(y|x) + r/τ**. Only log R is computed; no probabilities are multiplied
  (see `docs/reward_log_space.md`). *Clarified 2026-11-26 in response to PI feedback (Mohammed
  Mahfoud): we confirm the TB loss is computed in log space; the code is unchanged.*
- For each reply: δ = log π(y|x) − log π_untuned(y|x) − r/τ (log-probs summed over the whole reply).
- log Z(x) is estimated as −mean(δ) over the 8 replies to the same prompt.
- Loss = mean of (δ + log Z)², i.e. the variance of δ within each group. It is zero when the policy's
  log-ratios match the reward exactly.
- τ chosen on the dev set from {0.01, 0.03, 0.1, 0.3}: **τ = 0.03**.

## 3. Evaluation sets (never used in training)

Greedy decoding. Attack success is judged by the **HarmBench classifier** (Llama-2-13B);
refusals by WildGuard.

| Set | Source | n | Measures |
|---|---|---|---|
| Held-out prefill | HarmBench + one of 24 prefill phrases never used in training | 200 | Unseen compliant openers |
| Harmful prefix 10 / 20 / 40 tokens | HarmBench; reply starts with the first k tokens of a real harmful reply from the untuned model | 124 each | Recovery after harmful text |
| Jailbreak templates | HarmBench in 5 wrappers (refusal suppression, prefix injection, both, fiction role-play, research framing) | 200 × 5 | Unseen attack families |
| XSTest | Safe prompts that sound unsafe | 250 | False refusal |
| OR-Bench-Hard | Hard over-refusal prompts | 300 | False refusal |
| GSM8K | Test set | 200 | Maths accuracy |
| **Dev set** | JailbreakBench: 83 harmful (50 with harmful prefixes), 96 benign; overlap removed | | Choosing τ; second check |

## 5. Takeaways

1. **Pure GRPO is best.** It is the only method that lowers both attack success and false refusals
   relative to the untuned model.
2. **SFT + GRPO is slightly worse than pure GRPO** on harmful prefixes and templates, and does not
   reduce over-refusal. SFT trains only on the best of the model's own replies, so on its own it
   barely changes attack success (templates 70%) and gives GRPO little head start. It does lower
   over-refusal (OR-Bench-Hard 22% after SFT), but the GRPO stage, regularised toward the untuned
   model, undoes that (back to 33%). (The earlier 50% OR-Bench-Hard figure was mostly a
   reward-noise bug, since fixed.)
3. **GFlowNet does not match GRPO at the same budget.** It matches on single-phrase prefills, but
   is much worse on harmful prefixes and templates (paired on all hard attacks: harmful only under
   GRPO 43, only under TB 204; p ≈ 3e-26). This holds for every τ tried, for 100 steps as well as
   30, and on the dev set. TB stops once it is close to its target π_untuned · exp(r/τ) rather than
   pushing reward up, and its gradients are large and clipped on most steps. It never increased
   over-refusal.
