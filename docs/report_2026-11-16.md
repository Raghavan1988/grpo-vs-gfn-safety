# GFlowNet baseline on Qwen3-8B: status report (16 Nov)

**Setup.** Qwen3-8B (thinking off), LoRA rank 32. GRPO and trajectory balance (TB) use identical
prompts (16 per step: 8 prefilled harmful, 2 plain harmful, 3 benign, 3 maths), 8 sampled replies
per prompt (T = 1.0), WildGuard rewards, untuned model as reference, 30 steps. TB loss: within-group
variance of log π/π_ref − r/τ (batch log Z). Evaluation is greedy, judged by the HarmBench
classifier (attacks) and WildGuard (refusals). One seed per run. New: a JailbreakBench dev set
(83 harmful / 96 benign, overlap removed) for choosing τ.

## 1. Does GFlowNet match GRPO? No, at a matched budget.

| Test set (%) | Held-out prefill | Harmful prefix 10 / 40 tok | Templates (any) | XSTest FR | OR-Hard FR | GSM8K |
|---|---|---|---|---|---|---|
| Untuned | 42.0 | 98 / 98 | 72.0 | 4.0 | 32.0 | 94 |
| **GRPO** | 10.5 | **26 / 61** | **43.0** | **2.4** | **20.3** | 94.5 |
| TB τ=0.03 (best τ) | 11.0 | 54 / 77 | 66.5 | 5.2 | 33.3 | 96 |
| TB τ=0.03, 100 steps | 17.5 | 44 / 82 | 61.0 | 4.4 | 24.0 | 95.5 |

- Holds for every τ in {0.01, 0.03, 0.1, 0.3}, for 30 and 100 steps, and on the dev set
  (prefix-10: GRPO 24% vs TB 46–50%; templates: 43% vs 68%).
- Paired on all hard attacks: harmful only under GRPO 43, only under TB 204 (McNemar p ≈ 3e-26).
- **Why:** TB pulls the policy toward π_ref·exp(r/τ) and stops once it is close; it does not keep
  pushing reward up. Its gradients are large (norms 50–688) and clipped on most steps, so the
  effective step is small. More steps (100 vs 30) barely help. TB never raised over-refusal.

## 2. Why SFT + GRPO was worse than pure GRPO

| Test set (%) | Templates (any) | Prefix 40 tok | OR-Hard FR |
|---|---|---|---|
| SFT only | 70.0 | 88 | 22.0 |
| SFT+GRPO, old code (reported 14 Nov) | 53.0 | 76 | 50.0 |
| SFT+GRPO, current code, ref = untuned | 49.5 | 71 | 33.0 |
| SFT+GRPO, current code, ref = SFT | 61.5 | 70 | 26.7 |

- The 50% over-refusal was mostly a **reward-noise bug**: group normalisation amplified tiny
  WildGuard differences between equally safe replies. With the fix, it drops to 33%.
- SFT alone adds little attack resistance (it trains only on replies the model could already
  produce) but lowers over-refusal. Regularising GRPO toward SFT keeps that benefit (26.7%) but
  weakens template resistance (both effects p ≈ 0.03).
- GRPO alone still beats every SFT variant on attacks.

## 3. Corrections and fixes since last meeting

- Training replies are **sampled**, not greedy (SFT T = 0.7, 4 candidates; GRPO/TB T = 1.0,
  8 replies). Greedy is used only for evaluation.
- Added a dev set (JailbreakBench); test-set conclusions hold on it.
- Training is now preemption-safe (optimizer state checkpointed; resumed runs match uninterrupted
  ones in a test).

## 4. Proposed next steps (for discussion)

1. **Report the negative result** as the AR finding: with an untuned reference, TB ≡ KL-regularised
   RL in objective, and in practice GRPO's optimiser wins at this budget.
2. Or give TB one fair second chance, pre-registered: **off-policy TB with a replay buffer** of safe
   recoveries on deep harmful prefixes (where GFlowNets' ability to learn from off-policy data
   should help), and **WildJailbreak** (adversarial harmful + adversarial benign), where reward-
   proportional diversity could reduce over-refusal.
3. Either way: 3 seeds of GRPO and the best TB before any claim.
